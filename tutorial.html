純前端 Edge AI 路口人車安全偵測教學

本手冊完整記錄 SafeRoad AI 如何在「零伺服器、零採購成本」的條件下，透過瀏覽器直接執行 AI 模型，完成街景照片中的行人與車輛辨識，並即時運算「未禮讓行人」的空間交會衝突。

01

計畫動機與學習目標

傳統「科技執法」或智慧監控通常需要採購數十萬甚至百萬元的專用攝影機與 GPU 主機，導致偏鄉或一般校園巷弄難以普及。本專案核心概念為：直接將現有監視器畫面透過 Web 前端進行邊緣運算，實現平民化的智慧交通守護。

零主機成本
使用者自己的電腦/手機運算，省去維護雲端伺服器費用。
保障用路人隱私
影像完全留在前端瀏覽器處理，不需上傳遠端，無外流風險。
秒級即時反應
省去上傳與下載的網路來回時間，直接本機 50~100ms 輸出結果。
02

核心名詞「大白話」速查表

面對技術評審或老師提問時，請用以下生活化比喻進行說明：

專業技術名詞 白話怎麼講 直覺生活比喻
邊緣運算 (Edge AI) 「直接在使用者網頁裡面跑 AI」 像自己拿計算機算題目，不用每題打電話回辦公室問。
模型推論 (Inference) 「模型看照片、認出東西的過程」 就像眼睛看到照片，大腦在 0.1 秒內反應出「那是機車」。
特徵提取 (Feature Extraction) 「AI 抓出車輪、把手或人臉輪廓」 人認機車不是死背整張照片，而是認「兩個輪子加車把」。
非極大值抑制 (NMS) 「刪掉重複畫出的框框」 AI 框同一台車畫了 5 個重疊框，只留下分數最高的那 1 個。
Roboflow API 「把照片傳給專門訓練好的專家」 像用 LINE 把路況傳給專家，專家秒標記好回傳給你。
03

系統運作流程與偵測原理

[使用者上傳照片] ──> [前端 Canvas 讀取像素] ──> [MobileNet/YOLO 特徵提取] ──> [過濾交通目標 (人/車)] ──> [幾何衝突演算 (人車同框?)] ──> [紅框告警 / 綠框常態]

第一階段：AI 目標檢測（辨識人與車）

神經網路將圖片縮小並掃描特徵（如車頭形狀、人體形體），預測出畫面上所有物體的類別與中心座標 $(x, y, w, h)$。系統設定信心門檻為 0.35，自動濾除非交通物件或地圖圖標。

第二階段：未禮讓行人衝突判定（決策邏輯）

系統將抓到的目標分成「弱勢行人（`person`）」與「動力載具（`car/motorcycle/bus/truck`）」：

  • 安全通行（綠標）：路口僅有單純車流通過，或僅有行人在行走，無交會風險。
  • 未禮讓高風險告警（紅標）：路口或斑馬線交會區域內，同時偵測到穿越行人與行駛中之載具，判定路權搶越，即刻標註紅色警報。

模型架構評估與選型

評估指標 方案 A：YOLOv8n (ONNX Runtime) 方案 B：MobileNetV2-SSD (TFJS)
檔案大小 約 12 MB (單一二進位檔) 約 2 ~ 3 MB (切碎分段加載)
校園網路相容性 易受 TANet 防火牆擋住或下載逾時 極佳，各類平板、學校桌機秒開秒跑
推論精確度 高，對台灣高密度機車辨識極佳 優良，滿足展示與原型驗證需求
專案最佳定位 本機開發環境 / 高階終端測試 線上 GitHub Pages 成果展示
05

核心程式實作精華（四步法）

步驟 1：引入輕量化 CDN 腳本
<!-- 引入 TensorFlow.js 與 COCO-SSD 目標檢測函式庫 -->
<script src="https://cdn.jsdelivr.net/npm/@tensorflow/tfjs@4.10.0/dist/tf.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/@tensorflow-models/coco-ssd@2.2.2/dist/coco-ssd.min.js"></script>
步驟 2：非同步加載模型並進行偵測
// 非同步加載模型
const model = await cocoSsd.load();

// 輸入上傳之路口圖片並取得預測清單
const predictions = await model.detect(imgElement);
步驟 3：過濾目標並判定人車衝突
// 1. 篩選信心值大於 0.35 之人與車
const targets = predictions.filter(p => p.score >= 0.35 && ['person', 'car', 'motorcycle'].includes(p.class));

// 2. 判定是否同時存在行人與車輛
const hasPerson = targets.some(t => t.class === 'person');
const hasVehicle = targets.some(t => ['car', 'motorcycle'].includes(t.class));
const isConflict = hasPerson && hasVehicle; // 觸發未禮讓行人告警
步驟 4：動態 Canvas 標註繪圖
// 若有衝突顯示紅色，無衝突顯示綠色
ctx.strokeStyle = isConflict ? '#ef4444' : '#10b981';
ctx.strokeRect(x, y, width, height);
06

實務除錯心得（工讀生踩坑經驗分享）

地雷 1：學校電腦開網頁一直「轉圈圈卡死」

原因：代碼中寫死讀取本地 ./yolov8n.onnx（12MB），但 GitHub 沒有上傳該檔案；備用國外 CDN 又被學校 TANet 防火牆阻擋。
解法：展示端改用分段加載的 coco-ssd，檔案僅 2MB，學校網路與手機 4G/5G 皆能秒開。

地雷 2：高解析度街景照片上「標籤字體變米粒」

原因：固定設定 font: 14px，遇到 4K 或高解析度圖片時，文字比例縮小到看不見。
解法：改採動態比例計算 Math.floor(img.naturalWidth * 0.022)，無論照片多大，字體皆能清晰適配。

07

下階段後端演進規劃 (Roadmap)

目前前端版本已成功驗證「邊緣辨識可行性」。後續若要承接正式監視器串流，規劃升級之後端架構如下：

1. 連續串流介接 (RTSP / RTMP)
採用 Python FastAPI + OpenCV 解碼路口監視器即時影格。
2. 動態軌跡追蹤 (ByteTrack)
計算車輛行駛向量與車速，精準過濾路邊「靜止停放」之死車。
3. 事件日誌與資料庫 (PostgreSQL)
觸發未禮讓行人時，自動保存違規影像截圖並寫入違規資料表。
4. 自訂路口標註模型 (Roboflow)
訓練台灣特殊無號誌標線與混流車種專屬權重檔。
