純前端 Edge AI 路口人車安全偵測實作手冊

本教材完整記錄 SafeRoad AI 如何在「零主機採購、零伺服器維護」的條件下，直接於瀏覽器本地執行輕量神經網路，即時辨識行人與車輛，並即時演算「未禮讓行人」的空間交會衝突。

01

計畫動機與核心效益

傳統科技執法需採購百萬專用攝影機與 GPU 主機，偏鄉與校園周邊難以推廣。本專案核心目標：直接利用既有監視器畫面透過前端邊緣運算，打造平民化的交通安全網。

零主機成本
使用者自己的瀏覽器端運算，省去維護雲端伺服器的大筆租金。
保障用路人隱私
影像完全留在前端記憶體處理，不外傳至遠端，無資料外洩風險。
秒級即時反應
省去上傳與下載的網路來回延遲，50~100ms 內完成推論標註。
02

核心名詞「大白話」速查表

開會討論或向非技術同仁說明時，可用以下比喻快速表達：

專業技術名詞 白話怎麼講 直覺生活比喻
邊緣運算 (Edge AI) 「直接在使用者網頁裡面跑 AI」 像自己拿計算機算題目，不用每題打電話回總部問。
模型推論 (Inference) 「模型看照片、認出東西的過程」 就像眼睛看到照片，大腦在 0.1 秒內反應出「那是機車」。
特徵提取 (Feature Extraction) 「AI 抓出車輪、把手或人臉輪廓」 人認機車不是死背整張照片，而是認「兩個輪子加車把」。
非極大值抑制 (NMS) 「刪掉重複畫出的邊界框」 AI 框同一台車畫了 5 個重疊框，只留下分數最高的那 1 個。
Roboflow API 「把照片傳給特定訓練好的雲端大腦」 像用通訊軟體把照片傳給專家，請專家在 0.5 秒內圈出答案回傳。
03

系統運作流程與偵測原理

[上傳路口街景] ──> [前端 Canvas 提取張量] ──> [深度神經網路特徵分析] ──> [篩選交通實體 (人/車)] ──> [人車交會衝突演算] ──> [紅框告警 / 綠框常態]

第一階段：AI 目標檢測（辨識人與車）

神經網路將圖片正規化並抽取高階幾何特徵，預測出物體分類與邊界框座標 $(x, y, w, h)$。系統將過濾信心門檻定為 0.35（巷弄可微調至 0.28），有效排除街景地圖圖標等背景雜訊。

第二階段：未禮讓行人衝突判定（決策邏輯）

系統將辨識目標分類為「弱勢行人（`person`）」與「動力載具（`car/motorcycle/bus/truck`）」：

常態通行（安全綠標）
畫面中僅有單純車流通行，或僅有行人在安全範圍活動，無空間路權衝突。
未禮讓行人（高風險紅標）
路口交會動線上同時鎖定穿越行人與行駛車輛，自動觸發紅色告警並提醒停讓。
04

模型架構評估與選型

評估指標 方案 A：YOLOv8n (ONNX Runtime) 方案 B：MobileNetV2-SSD (TFJS)
檔案體積 約 12 MB (單一二進位模型檔) 約 2 ~ 3 MB (切碎分段加載)
校園網路相容性 易受 TANet 防火牆阻擋或連線逾時 極佳，各類平板、學校桌機秒開秒跑
推論精確度 高，對高密度機車辨識度極佳 優良，滿足展示與原型驗證需求
專案最佳定位 本機開發環境 / 高階終端測試 線上 GitHub Pages 成果展示
05

核心程式實作精華（四步法）

步驟 1：引入輕量化 CDN 腳本
<!-- 引入 TensorFlow.js 與 COCO-SSD 目標檢測函式庫 -->
<script src="https://cdn.jsdelivr.net/npm/@tensorflow/tfjs@4.10.0/dist/tf.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/@tensorflow-models/coco-ssd@2.2.2/dist/coco-ssd.min.js"></script>
步驟 2：非同步加載模型並進行偵測
// 非同步加載輕量化模型
const model = await cocoSsd.load();

// 輸入上傳之路口圖片並取得預測清單
const predictions = await model.detect(imgElement);
步驟 3：過濾目標並判定人車衝突
// 1. 篩選信心值大於 0.35 之人與車
const targets = predictions.filter(p => p.score >= 0.35 && ['person', 'car', 'motorcycle'].includes(p.class));

// 2. 判定是否同時存在行人與車輛
const hasPerson = targets.some(t => t.class === 'person');
const hasVehicle = targets.some(t => ['car', 'motorcycle'].includes(t.class));
const isConflict = hasPerson && hasVehicle; // 觸發未禮讓行人告警
步驟 4：動態 Canvas 標註繪圖
// 若有衝突顯示紅色，無衝突顯示綠色
ctx.strokeStyle = isConflict ? '#ef4444' : '#10b981';
ctx.strokeRect(x, y, width, height);
06

團隊實測反饋與避坑經驗

團隊實測反饋：無號誌巷弄辨識挑戰

現象：內部實測反映「有紅綠燈之主幹道路口辨識率高，但無號誌小巷弄較難抓到人車」。
分析：巷弄背景存在大量招牌、鐵捲門與路邊違停車輛，人車特徵容易被遮蔽（Occlusion）。
因應對策：目前展示端先將偵測門檻彈性降至 0.28 提高靈敏度；並正式列為下一階段使用 Roboflow 進行台灣在地巷弄資料集微調訓練之核心目標！

踩坑 1：校園網路環境模型載入卡死

原因：前版嘗試載入 12MB 之單一 ONNX 模型，易受校園 TANet 防火牆阻擋或逾時。
解法：展示端改用分段加載的 2MB 輕量 MobileNet-SSD，各類平板與手機行動網路皆能秒開。

踩坑 2：高解析度街景照片上標籤字體失真

原因：固定設定 14px 字體，遇 4K 照片時文字縮小至無法辨識。
解法：改採畫布寬度百分比動態縮放 Math.floor(img.naturalWidth * 0.022)。

07

AI (Gemini) 輔助系統生成步驟全紀錄

如何透過精準提示詞（Prompts）讓 AI 協同完成從需求到部署的全流程

階段一：需求定義與純前端原型提示 (Prompting) 架構定調

開發痛點：傳統科技執法需百萬主機，學生專題/偏鄉無伺服器預算。
向 Gemini 下達的核心提示詞：

"我想做一個 SafeRoad AI 交通安全檢測網頁，不要架設後端 Python 伺服器，請直接用純 HTML + Tailwind CSS + TensorFlow.js (coco-ssd)，讓使用者上傳路口街景照片後，純前端在瀏覽器辨識出『行人』與『車輛』。"
階段二：交通決策邏輯演算法注入 邏輯生成

開發痛點：模型只會畫框框，不知道什麼叫「未禮讓行人」。
向 Gemini 下達的核心提示詞：

"請在原本的偵測代碼中加入判斷：當畫面上同時偵測到『弱勢行人 (person)』與『動力車輛 (car/motorcycle)』時，將所有方框即時由綠色切換為紅色高風險告警，並在下方跳出『未禮讓行人預警』的狀態通知卡片。"
階段三：環境踩坑與模型降載重構 除錯迭代

開發痛點：嘗試改用 12MB 的 YOLOv8-ONNX 模型，但在學校 TANet 網路會卡死在加載階段。
向 Gemini 下達的核心提示詞：

"線上展示版本不要再連線下載 12MB 的大型 ONNX 權重檔，請退回採用 2MB、可分段加載的 MobileNet-SSD 架構，但介面保留 Roboflow API 與自訂模型的擴充欄位，確保老舊電腦與手機行動網路都能秒開秒跑。"
階段四：視覺 UI 優化與講義網頁化 成果落地

開發痛點：死白背景過於刺眼、且需配合專案規格整理為線上技術講義網頁。
向 Gemini 下達的核心提示詞：

"請參考線上教材網頁結構，幫我生成一份 tutorial.html 教學講義。不要刺眼的大片死白，採用柔和的 slate 灰階與科技藍卡片層次，將專有名詞改寫為通俗白話，並包含從前端到後端演進的架構圖。"
08

下階段後端演進規劃 (Roadmap)

目前前端版本已成功驗證「邊緣即時辨識之可行性」。若後續計畫需串接實體路口監視器連續影像，架構演進規劃如下：

1. 連續串流介接 (RTSP / RTMP)
採用 Python FastAPI + OpenCV 解碼路口監視器即時影格。
2. 動態軌跡追蹤 (ByteTrack)
計算車輛行駛向量與車速，精準過濾路邊「靜止停放」之死車。
3. 事件日誌與資料庫 (PostgreSQL)
觸發未禮讓行人時，自動保存違規影像截圖並寫入違規資料表。
4. 自訂路口標註模型 (Roboflow)
訓練台灣特殊無號誌標線與混流車種專屬權重檔。
